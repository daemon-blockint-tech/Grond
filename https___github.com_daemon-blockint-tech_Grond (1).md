# Boris Cherny, creator of Claude Code, membagikan berbagai teknik praktis untuk memaksimalkan penggunaan asisten coding berbasis terminal ini dalam membangun alur kerja yang efisien.

### **Fungsionalitas Inti dan Persiapan Awal**

Claude Code adalah asisten agentic yang dirancang untuk membangun fitur, menulis file utuh, dan memperbaiki bug secara mandiri, bukan sekadar pelengkap baris kode. Karena berjalan di terminal, alat ini kompatibel dengan berbagai IDE seperti VS Code, Xcode, hingga Vim.

* **Instalasi:** Dapat diinstal melalui Node.js dengan perintah npm install -g @anthropic-ai/claude-code.
* **Pengaturan Terminal:** Gunakan /terminal-setup untuk mengaktifkan "Shift + Enter" guna membuat baris baru tanpa perlu menggunakan garis miring terbalik (backslashes).
* **Dikte Suara:** Pengguna Mac OS dapat mengaktifkan fitur dikte di pengaturan aksesibilitas untuk memberikan perintah suara, yang seringkali lebih cepat daripada mengetik instruksi yang kompleks.


### **Eksplorasi dan Tanya Jawab Kode**

Langkah awal yang disarankan adalah menggunakan fitur Q\&A untuk memahami basis kode.

* **Konteks Mendalam:** Alat ini tidak hanya melakukan pencarian teks biasa, tetapi bisa menjelaskan cara sebuah kelas diinstansiasi atau menemukan contoh penggunaan di seluruh proyek.
* **Analisis Riwayat Git:** Pengguna bisa bertanya tentang alasan di balik perubahan kode tertentu. Claude akan memeriksa riwayat git dan isu terkait untuk merangkum alasan teknis di balik struktur kode tersebut.
* **Privasi Lokal:** Claude Code bekerja secara lokal tanpa perlu melakukan pengindeksan ke database jarak jauh, sehingga kode Anda tetap privat dan tidak digunakan untuk melatih model generatif.


### **Alur Kerja Pengeditan dan Agen**

Claude menggunakan alat bantu seperti pengeditan file, perintah bash, dan pencarian file untuk menyelesaikan tugas.

* **Perencanaan Terlebih Dahulu:** Untuk fitur yang besar, disarankan meminta Claude membuat rencana dan meminta persetujuan sebelum mulai menulis kode. Ini mencegah asisten membangun sesuatu yang tidak sesuai dengan keinginan pengguna.
* **Iterasi dengan Umpan Balik:** Claude sangat efektif jika diberikan cara untuk memeriksa hasilnya sendiri. Dengan menyediakan unit test atau alat bantu seperti Puppeteer untuk screenshot, Claude dapat melakukan iterasi otomatis hingga kode berfungsi dengan sempurna.
* **Otomatisasi Git:** Perintah sederhana seperti "commit and push" memungkinkan Claude membuat pesan commit yang sesuai format, membuat branch, hingga membuka Pull Request di GitHub secara otomatis.


### **Manajemen Konteks (Claude.md)**

Kustomisasi konteks adalah kunci untuk meningkatkan kecerdasan asisten dalam proyek spesifik.

* **File claude.md:** File ini ditempatkan di root proyek untuk menyimpan keputusan arsitektur, panduan gaya (style guide), atau perintah bash yang sering digunakan. File ini akan dibaca otomatis setiap sesi dimulai.
* **Memori Hierarkis:** Pengguna dapat meletakkan file claude.md di dalam folder tertentu agar konteks tersebut hanya dimuat saat Claude bekerja di direktori tersebut.
* **Perintah Memori:** Menggunakan simbol pagar (\#) diikuti instruksi akan memerintahkan Claude untuk mengingat informasi tersebut secara permanen dalam memori proyek.


### **Tips Pengguna Mahir (Power User)**

* **Auto-Accept Edits:** Tekan "Shift + Tab" untuk beralih ke mode persetujuan otomatis pada pengeditan file, sehingga Anda tidak perlu menyetujui setiap perubahan kecil secara manual.
* **Mode Batch (SDK):** Dengan flag -p, Claude Code dapat digunakan sebagai utilitas Unix. Anda bisa menyalurkan (pipe) output dari perintah lain (seperti log atau status git) ke dalam Claude untuk dianalisis atau diproses lebih lanjut.
* **Kontrol Sesi:** Gunakan tombol "Escape" untuk menghentikan proses yang sedang berjalan dengan aman tanpa merusak sesi atau file yang sedang diedit.

Boris Cherny menekankan bahwa Claude Code paling berguna kalau diperlakukan sebagai “agen pengembang” penuh, bukan sekadar autocomplete, dan seluruh tipsnya berfokus pada cara membangun alur kerja coding yang efisien di terminal.[^2_1][^2_2]

## Inti Claude Code dan setup awal

Claude Code adalah asisten coding berbasis terminal yang bisa menjelajah kode, menulis file utuh, menjalankan perintah bash, hingga mengelola git sebagai satu loop agentic (kumpulkan konteks → ambil aksi → verifikasi hasil).[^2_3][^2_4] Alat ini berjalan di shell sehingga bisa dipakai berdampingan dengan IDE apa pun seperti VS Code, Xcode, atau Vim.[^2_3]

Poin setup penting yang sejalan dengan materi Boris dan dokumentasi resmi:

- Instalasi global via Node.js dengan `npm install -g @anthropic-ai/claude-code` untuk menjalankan perintah `code` dari mana saja.[^2_3][^2_5]
- Konfigurasi terminal (misalnya lewat perintah /terminal-setup atau binding serupa) agar Shift+Enter membuat baris baru, supaya prompt panjang mudah ditulis tanpa backslash.[^2_3]
- Di macOS, mengaktifkan dikte suara di pengaturan aksesibilitas membuat instruksi panjang (misalnya jelaskan bug, minta refactor besar) jauh lebih cepat daripada mengetik.[^2_6][^2_7]


## Eksplorasi \& tanya jawab kode

Boris menganjurkan memulai sesi dengan eksplorasi dan Q\&A, bukan langsung “tolong tulis fitur X”.[^2_2][^2_8] Claude Code bisa:

- Menjawab pertanyaan mendalam tentang codebase, seperti bagaimana sebuah kelas diinstansiasi atau contoh penggunaan fungsi di seluruh proyek, karena ia menggunakan kombinasi pencarian file, pembacaan, dan reasoning daripada sekadar grep literal.[^2_3][^2_4]
- Membaca riwayat git dan issue terkait untuk menjelaskan “kenapa” di balik perubahan tertentu, sehingga Anda bisa memahami motif dan trade-off desain yang diambil sebelumnya.[^2_1][^2_9]
- Bekerja secara lokal lewat sistem tools tanpa mengindeks ke layanan jarak jauh; desainnya memang membatasi akses hanya melalui tool yang diotorisasi sehingga menjaga privasi codebase dan meminimalkan kebocoran data.[^2_1][^2_4][^2_5]


## Alur kerja pengeditan \& agen

Dalam workflow ala Boris, Claude Code menggunakan tiga kemampuan inti: baca/edit file, jalankan bash, dan navigasi kode untuk menyelesaikan tugas end‑to‑end.[^2_1][^2_4] Strategi yang ia tekankan:

- Untuk fitur non-trivial, masuk dulu ke “Plan Mode”: minta Claude membuat rencana langkah demi langkah dan validasi rencana itu sebelum menyentuh kode, supaya tidak terjadi “agen berubah terlalu banyak hal yang tidak Anda minta”.[^2_2][^2_10]
- Beri Claude cara memverifikasi pekerjaannya: sediakan unit test, script e2e, atau alat seperti Puppeteer untuk screenshot; dengan feedback loop yang jelas, kualitas hasil biasanya naik 2–3× karena agen bisa menjalankan test, membaca output, lalu mengiterasi sendiri.[^2_2][^2_4]
- Manfaatkan otomasi git: perintah singkat seperti “commit and push” atau “buat PR untuk perubahan ini” memungkinkan Claude membuat branch, menulis pesan commit yang rapi, menjalankan test, hingga membuka Pull Request di GitHub.[^2_3][^2_10][^2_5]


## Manajemen konteks dengan claude.md

Boris dan dokumentasi resmi menekankan pentingnya meng-“eksternalisasi konteks” dalam file teks, bukan hanya mengandalkan memori model.[^2_1][^2_7][^2_8] Di Claude Code, ini difasilitasi oleh:

- `claude.md` di root proyek untuk menyimpan keputusan arsitektur, style guide, konvensi git, perintah bash favorit, dan konteks bisnis; file ini otomatis dibaca setiap sesi sehingga Claude memahami “aturan main” proyek Anda sejak awal.[^2_3][^2_10][^2_4]
- `claude.md` bertingkat di subfolder agar aturan atau konteks khusus modul hanya dipakai saat Claude bekerja di direktori tersebut, misalnya aturan khusus untuk app mobile vs backend.[^2_3][^2_10]
- Sintaks “memori” (misalnya instruksi yang diawali tanda pagar) yang memberi tahu Claude untuk mengingat informasi tertentu sebagai memori persisten proyek, memperkuat konsistensi di sesi berikutnya.[^2_3][^2_4]


## Fitur power‑user dan tips lanjutan

Sejumlah trik yang membuat Claude Code jauh lebih produktif di tangan pengguna mahir:[^2_6][^2_11]

- Mode auto‑accept edits (sering diakses dengan Shift+Tab setelah Plan Mode): setelah rencana disepakati, Anda bisa membiarkan Claude menerapkan batch edit tanpa harus meng-approve setiap perubahan kecil satu per satu.[^2_2][^2_10]
- Mode batch / SDK: dengan flag seperti `-p`, Claude Code bisa dipakai sebagai utilitas Unix yang membaca input dari pipe (misalnya log panjang, output test, atau `git status`) lalu menganalisis atau merapikannya otomatis.[^2_7][^2_5]
- Kontrol sesi yang eksplisit: tombol Escape atau perintah penghentian setara memungkinkan Anda menghentikan proses yang sedang berjalan tanpa merusak sesi atau meninggalkan file dalam keadaan setengah teredit.[^2_3][^2_4]

Jika tujuan Anda di Jakarta adalah benar‑benar mengintegrasikan Claude Code ke workflow harian, apa dulu editor utama yang Anda pakai sekarang (VS Code, JetBrains, Vim, atau yang lain)?

## Apa itu Grond?

**Grond** adalah platform **Agentic Open Source Intelligence (OSINT)** berbasis hybrid Python + TypeScript yang dirancang untuk tim analis keamanan dan intelijen.  Fokus utamanya adalah pipeline *evidence-first* — setiap output dilengkapi provenance dan audit trail, bukan sekadar generasi teks bebas dari LLM.

## Tech Stack

| Layer | Teknologi |
| :-- | :-- |
| **Backend API** | Python 3.12+, FastAPI |
| **Orchestrasi AI** | LangGraph (Python), Claude Agent SDK / OpenRouter (TypeScript) |
| **OSINT Tools** | Shodan, Tavily, X/Twitter API v2, python-nmap, SEC EDGAR |
| **Database** | PostgreSQL + pgvector, Redis, Neo4j, Qdrant (opsional), S3-compatible |
| **Frontend** | Next.js (analyst dashboard) |
| **Queue** | BullMQ (TypeScript) |
| **Observability** | OpenTelemetry, structlog/pino, Sentry (opsional) |

## Arsitektur Pipeline

Grond menjalankan empat tahap utama secara berurutan:

1. **Collect** — Kumpulkan data dari Shodan, Tavily, Twitter, dll.
2. **Enrich** — Koroborasi, relevansi domain, deduplikasi
3. **Verify** — Validasi bukti sebelum dijadikan laporan
4. **Report** — Generate `IntelReport` terstruktur (deterministic) + narasi LLM opsional

## Struktur Repositori

| Folder | Fungsi |
| :-- | :-- |
| `src/` | FastAPI app, pipeline stages, tool adapters, Pydantic models |
| `orchestration/` | TypeScript agents, BullMQ jobs, Neo4j client |
| `examples/` | Next.js analyst dashboard \& company research UI |
| `agents/` | Markdown playbook untuk agent OSINT |
| `recon/` | Script lokal untuk Nmap/Ncrack (untuk lab authorized) |
| `docs/` | Dokumentasi authorization \& incident response |

## Quick Start

```bash
# 1. Clone dan install
git clone https://github.com/daemon-blockint-tech/Grond.git
cd Grond
uv sync --extra dev

# 2. Konfigurasi environment
cp .env.example .env
# Edit .env: isi SHODAN_API_KEY, TAVILY_API_KEY, DATABASE_URL, dll.

# 3. Jalankan API
uv run uvicorn src.api.main:app --host 127.0.0.1 --port 8000 --reload --env-file .env
```

Setelah berjalan, akses health check di `http://127.0.0.1:8000/api/v1/health` dan dokumentasi OpenAPI di `http://127.0.0.1:8000/docs`.

## Keamanan \& Etika

Grond membedakan dua mode penggunaan dengan tegas:

- **Passive OSINT** (Shodan, Tavily, web) — diperbolehkan, tunduk pada ToS provider dan hukum yang berlaku.
- **Active scanning** (Nmap) — **diblokir secara default**, hanya bisa diaktifkan dengan otorisasi eksplisit via environment variable `GROND_AUTHORIZED_SCAN_TARGETS` atau database grants, disertai mekanisme *human-in-the-loop*.


## Status Proyek

Repositori sudah cukup matang dengan CI/CD aktif (`.github/workflows/ci.yml` menjalankan pytest dan build Next.js di setiap push/PR), file `MATURITY_REPORT.md` tersedia, lisensi MIT, serta dokumentasi `CLAUDE.md` dan `AGENTS.md` untuk panduan kontribusi berbasis AI.

* **Memori Hierarkis:** Pengguna dapat meletakkan file claude.md di dalam folder tertentu agar konteks tersebut hanya dimuat saat Claude bekerja di direktori tersebut.
* **Perintah Memori:** Menggunakan simbol pagar (\#) diikuti instruksi akan memerintahkan Claude untuk mengingat informasi tersebut secara permanen dalam memori proyek.


### **Tips Pengguna Mahir (Power User)**

* **Auto-Accept Edits:** Tekan "Shift + Tab" untuk beralih ke mode persetujuan otomatis pada pengeditan file, sehingga Anda tidak perlu menyetujui setiap perubahan kecil secara manual.
* **Mode Batch (SDK):** Dengan flag -p, Claude Code dapat digunakan sebagai utilitas Unix. Anda bisa menyalurkan (pipe) output dari perintah lain (seperti log atau status git) ke dalam Claude untuk dianalisis atau diproses lebih lanjut.
* **Kontrol Sesi:** Gunakan tombol "Escape" untuk menghentikan proses yang sedang berjalan dengan aman tanpa merusak sesi atau file yang sedang diedit.

Teks yang Anda kirim sudah sangat bagus sebagai ringkasan praktis penggunaan Claude Code ala Boris Cherny; tidak perlu banyak koreksi substansi, hanya bisa dipertajam sedikit jika mau dijadikan artikel/slide.

# dalam konteks https://github.com/daemon-blockint-tech/Grond.git

Dalam konteks **Grond**, tips Boris Cherny tentang Claude Code bisa dipakai untuk membangun workflow “developer + agent” yang sangat kuat, terutama karena Grond sendiri sudah “agentic OSINT platform” dengan banyak komponen kompleks.  Intinya, Anda bisa memakai Claude Code sebagai co‑maintainer untuk memahami, mengembangkan, dan mengoperasikan Grond secara lebih aman dan terstruktur.

## 1. Eksplorasi codebase Grond dengan Q\&A

Grond punya struktur yang cukup besar: FastAPI di `src/api/`, pipeline OSINT di `src/pipeline/`, adapters tools di `src/tools/`, TypeScript agents di `orchestration/`, dan dashboard Next.js di `examples/grond-dashboard/`.  Di sini pola Q\&A ala Boris sangat berguna:

- Mulai sesi Claude Code dari root repo `Grond/`, lalu tanya hal-hal seperti:
    - “Jelaskan arsitektur pipeline collect → enrich → verify → report di `src/pipeline/` dan hubungan dengan `src/core/orchestrator.py`.”
    - “Tunjukkan bagaimana tool Shodan dan Tavily diimplementasikan di `src/tools/` dan bagaimana mereka dipanggil dari API.”
- Gunakan fitur **pencarian konteks mendalam** Claude Code untuk melacak bagaimana model `IntelReport` didefinisikan di `src/models/` dan di mana dia digunakan di endpoint FastAPI. [^6_1]

Dengan cara ini, Anda menjadikan Claude Code sebagai pemandu tur arsitektur Grond sebelum menyentuh perubahan apa pun.

## 2. Manfaatkan riwayat git + docs yang sudah kaya

Grond sudah menyediakan banyak dokumentasi internal: `README.md`, `MATURITY_REPORT.md`, `CLAUDE.md`, `AGENTS.md`, dan berbagai file di `docs/` (termasuk `security-authorization.md` dan `incident-response.md`).

- Gunakan fitur **analisis riwayat git** Claude Code untuk pertanyaan seperti:
    - “Kenapa model otorisasi active scan diubah di commit X? Apa kaitannya dengan `docs/security-authorization.md`?” [^6_2]
- Minta Claude membaca `MATURITY_REPORT.md` dan merangkum status kematangan tiap modul (API, pipeline, orchestration, UI), sehingga Anda tahu area mana yang aman untuk di-refactor dan mana yang masih eksperimental.

Boris menekankan: selalu pahami “mengapa” desain eksisting sebelum menyuruh agen melakukan refactor besar.

## 3. gunting-lem kcontext ke CLAUDE.md \& agents/

Grond sudah punya `CLAUDE.md` dan folder `agents/` yang berfungsi mirip konsep **claude.md + playbook** yang Boris sarankan.

- Tambahkan ke `CLAUDE.md` hal-hal khusus Grond:
    - gaya penulisan endpoint di `src/api/`,
    - pola logging/audit yang harus selalu ada di `src/tools/`,
    - aturan etika OSINT (singkron dengan `.cursor/rules/security-ethics.mdc` dan `docs/security-authorization.md`).
- Gunakan folder `agents/` untuk menyimpan prompt/panduan tugas spesifik, misalnya:
    - “Agent: tambah tool OSINT baru yang hanya pasif, tanpa active scanning.”
    - “Agent: modifikasi `examples/grond-dashboard` untuk menambah tab baru di Intel view.”

Dengan begitu, setiap sesi Claude Code terhadap repo Grond selalu dimulai dengan konteks domain yang benar, persis seperti pendekatan memori hierarkis dan claude.md yang Anda uraikan tadi. [^6_3]

## 4. Rencanakan dulu sebelum menyentuh pipeline OSINT

Pipeline `collect → enrich → verify → report` di Grond menyentuh banyak komponen: tools, database (PostgreSQL + pgvector, Redis, Neo4j, S3), dan model laporan.  Sesuai saran Boris, sebaiknya selalu:

1. Minta Claude Code membuat **rencana rinci** kalau Anda mau:
    - menambah sumber OSINT baru di `src/tools/` dan integrasinya ke `src/pipeline/`, atau
    - mengubah format `IntelReport` di `src/models/`. [^6_3]
2. Review rencana itu, koreksi bila ada bagian yang bertentangan dengan aturan otorisasi active scan atau kebijakan penyimpanan bukti.

Baru setelah plan disetujui, nyalakan mode auto‑edit/auto‑accept untuk patch kecil seperti wiring endpoint, penyesuaian schema, dan update test. [^6_3]

## 5. Umpan balik lewat test \& contoh UI Grond

Grond punya beberapa titik verifikasi yang ideal untuk pola *iterasi dengan umpan balik* ala Boris: [^6_3]

- **Test Python**: jalankan `uv run pytest` untuk memverifikasi perubahan di backend, lalu pipe output error ke Claude Code untuk diminta diagnosa dan perbaikan otomatis.
- **Linting**: gunakan `uv run ruff check .` dan pipe hasilnya; minta Claude memperbaiki semua masalah yang aman diperbaiki otomatis. [^6_4]
- **Next.js dashboard**:
    - Jalankan `examples/grond-dashboard` (npm ci + npm run dev).
    - Pakai Claude Code untuk menganalisis error log development, memperbaiki API call ke endpoint FastAPI (`/api/v1/*`), dan konsistensi tipe antara TypeScript dan schema backend.

Ini persis pola yang Boris anjurkan: Claude diberi “alat cek diri” berupa test, log, dan UI running, lalu diizinkan mengiterasi sampai hijau.

## 6. Otomatisasi git untuk perubahan multi-modul

Karena Grond mencakup Python backend, TS orchestration, dan Next.js UI, perubahan feature sering menyentuh banyak folder sekaligus.  Kombinasikan:

- Perintah **“commit dan push”** di Claude Code untuk:
    - membuat branch feature,
    - menulis pesan commit yang menjelaskan perubahan di src/api, src/tools, orchestration, dan examples,
    - membuka Pull Request yang merangkum perubahan terhadap pipeline OSINT. [^6_3][^6_5]
- Sertakan dalam PR summary link ke dokumen relevan (misalnya `docs/security-authorization.md` jika menyentuh active scan) supaya reviewer manusia bisa fokus ke aspek risiko.

Ini membantu menjaga guardrail keamanan dan audit trail yang memang merupakan pilar desain Grond.

## 7. Mode batch untuk log OSINT \& queue

Grond menggunakan BullMQ, Redis, dan berbagai service OSINT — output log bisa panjang.  Mode batch/SDK Claude Code (flag `-p`) yang Anda sebut sangat cocok untuk: [^6_6]

- Pipe log pipeline (misal dari `uvicorn` atau worker BullMQ) ke Claude untuk:
    - ringkasan error,
    - identifikasi pola kegagalan pada tool tertentu (misalnya Shodan sering timeout),
    - usulan retry/backoff lebih baik. [^6_7]
- Analisis log audit otorisasi active scan untuk memastikan konfigurasi `GROND_AUTHORIZED_SCAN_TARGETS` berjalan seperti yang diharapkan.

Dengan cara ini, Claude Code dipakai bukan hanya untuk coding, tapi juga sebagai analis operasional Grond.

# apa titik kurang dari https://github.com/daemon-blockint-tech/Grond.git yang perlu di perbaiki

Secara garis besar, Grond sudah cukup matang dan well‑documented, tapi masih ada beberapa titik yang bisa diperbaiki/ditajamkan kalau tujuannya adalah production‑grade platform OSINT dengan contributor eksternal. Semua poin ini murni dari apa yang tertulis di repo, bukan kritik ke implementasi internal yang saya tidak lihat langsung.

## 1. Onboarding \& UX pengembang

- **Banyak komponen, satu README**: README sudah padat, tapi developer baru tetap harus melompat ke beberapa folder (`orchestration/`, `examples/*`, `docs/*`) tanpa ada “aliran tugas” yang sangat eksplisit (misalnya: *“kalau kamu hanya mau backend, lakukan A; kalau mau full stack + TS agents, lakukan B”*).
- **.env contoh sangat kaya, tapi tidak diurutkan per skenario**: `.env.example` dijadikan “checklist otoritatif”, namun belum ada contoh konfigurasi minimal per use case: *single‑node lab*, *analyst desktop*, atau *cluster kecil dengan BullMQ*.

Perbaikan yang mungkin:

- Tambahkan bagian “getting started per persona” di README, misalnya: *Analyst only*, *Backend dev*, *TS agent dev*, *SecOps*.
- Buat beberapa file seperti `.env.lab`, `.env.demo`, `.env.prod-example` yang reuse dari `.env.example` tapi sudah disesuaikan tipikal topologi deployment.


## 2. Batasan keamanan \& compliance yang masih implisit

- **Pemisahan antara pasif \& aktif sudah ada, tapi belum dikaitkan ke model risiko**: README menekankan bahwa Nmap/active scans hanya untuk target berotorisasi dan ada `GROND_AUTHORIZED_SCAN_TARGETS`, DB grants, dan admin route.  Namun, belum ada contoh “policy template” untuk organisasi (misal SOC perusahaan, lembaga pemerintah) tentang siapa boleh mengubah variabel ini, bagaimana proses approval, dsb.
- **PII \& data sensitif hanya disentuh singkat**: ada catatan bahwa PII dan temuan sensitif perlu dasar hukum dan review analis, tapi belum ada best practice teknis (masking, redaction otomatis, retention policy) di README.

Perbaikan yang mungkin:

- Tambah *Security \& Governance Playbook* ringan di `docs/` dan link langsung dari README: form approval, contoh SOP, dan contoh konfigurasi env untuk “no‑active‑scan” mode.
- Tambah contoh konfigurasi redaction atau minimal pointer ke bagaimana menyambungkan ke sistem DLP / redaction eksternal.


## 3. Observability \& operasional belum sangat opinionated

- README menyebut dukungan **OpenTelemetry**, logging terstruktur (`structlog`, `pino`), dan opsional Sentry, tapi tidak memberi contoh *dashboard* atau *otel collector config* yang direkomendasikan.
- Tidak ada contoh “failure mode” yang dijelaskan: misalnya apa yang terjadi bila Qdrant atau Neo4j tidak tersedia, atau kalau Redis down ketika BullMQ masih mendorong job.

Perbaikan yang mungkin:

- Tambahkan satu sub-bab “Running in production” dengan contoh minimal: otel collector, grafana dashboard, dan pola retry/backoff yang dianjurkan.
- Dokumentasikan degradation path: misalnya “kalau Neo4j tidak dikonfigurasi, fitur X dan Y nonaktif, tapi pipeline tetap jalan”.


## 4. Konsistensi antara Python vs TypeScript layer

- Platform ini hybrid: Python untuk pipeline \& API, TypeScript untuk agent orchestration \& BullMQ workers.  README menjelaskan perannya, tapi belum ada sketsa kontrak versi API (mis. *this is how `POST /api/v1/scan` is expected to behave*), atau contoh error handling yang sama antara kedua sisi.
- Untuk kontributor baru di sisi TS, bisa terasa kurang jelas bagaimana cara menambah agent yang “benar” (misal pattern standard logging, nama queue, dan kebijakan timeout).

Perbaikan yang mungkin:

- Tambah satu dokumen singkat di `orchestration/` yang menjelaskan kontrak API penting, pola error umum, dan “checklist menambah agent baru”.
- Pastikan README atau `CLAUDE.md` menyatukan gaya coding: kapan pakai TS untuk logic, kapan cukup lewat Python.


## 5. Dokumentasi contoh UI masih tipis di README root

- README menyebut **Next.js analyst dashboard** dan **company‑research UI**, tetapi hanya mengarahkan pembaca ke README di masing-masing folder.
- Tidak ada screenshot atau deskripsi “use case utama” dari dashboard (misalnya tab Intel, Recon, Datasheet) di README utama, padahal ini membantu calon pengguna non‑developer memahami nilai produk.

Perbaikan yang mungkin:

- Tambahkan satu subsection ringkas “What the dashboard looks like” yang menjelaskan 2–3 skenario nyata (contoh: *threat recon domain tertentu, laporan intel per company, dsb*), plus 1–2 screenshot.
- Di root, tulis langkah cepat: “Untuk hanya mencoba UI tanpa otak TS agent, jalankan A/B; untuk full stack, jalankan C/D”.


## 6. Batas “maturity” tiap fitur tidak di-highlight di depan

- Ada file `MATURITY_REPORT.md` yang terdengar sangat berguna, tapi tidak semua pembaca README akan membukanya.
- Tanpa membaca file itu, sulit menilai: tool mana yang “production ready”, mana yang “experimental / PoC only”.

Perbaikan yang mungkin:

- Tarik ringkasan `MATURITY_REPORT.md` ke README (misalnya tabel kecil: *Stable*, *Beta*, *Experimental* untuk pipeline, tools tertentu, dashboard, dsb.).
- Tandai di README atau docs kalau ada tool yang sangat tergantung pada API pihak ketiga yang sering berubah (mis. Twitter/X).


## 7. Konteks “siapa seharusnya pakai Grond” bisa diperjelas

- Tagline “Agentic OSINT for teams that need corroboration, audit trails, and authorization boundaries” sudah bagus, tapi README belum banyak memberi contoh **peran organisasi** (SOC perusahaan, threat intel, red‑team OSINT, investigative journalism, dll.).
- Ini penting untuk calon adopter: mereka butuh tahu “ini cocok untuk kami atau terlalu berat/terlalu luas”.

Perbaikan yang mungkin:

- Tambah satu bagian singkat “Who this is for / not for” dengan beberapa persona dan non‑goal.

```markdown
  - Dashboard

  - Leave `GROND_DEV_BYPASS_NMAP_HITL` unset.

This profile is a good fit for:

- Corporate threat intel teams with strict boundaries.
- OSINT-only investigative work.
```

```markdown
# Security & governance playbook

Grond is built for evidence-first OSINT with explicit guardrails. This document outlines recommended governance practices for teams running Grond in production or semi-production settings.

## Roles

At minimum, define these roles in your organization:

- **Platform owner**  
  Owns the deployment of Grond (infrastructure, secrets, updates).

- **Security officer / approver**  
  Approves active-scan scopes and reviews changes to authorization config.

- **Analysts / operators**  
  Use Grond for investigations; do not change authorization or infra.

## Authorization for active scans

All active scanning (e.g. Nmap) must be:

1. **Explicitly authorized in writing** (ticket / email / contract).
2. **Scoped** to specific targets (domains, IPs, CIDRs).
3. **Configured** in one of:

   - `GROND_AUTHORIZED_SCAN_TARGETS` env variable (for simple lab setups).
   - Database-backed authorization tables (for larger deployments).

Recommended process:

- Any change to authorized targets:
  - Is made via change management (PR, ticket).
  - Is reviewed by the security officer.
  - Is logged and auditable.

See [security-authorization.md](security-authorization.md) for how the checks are enforced server-side.

## Handling PII and sensitive data

Grond may surface personally identifiable information (PII) or other sensitive findings in OSINT context.

Suggested practices:

- Define a **data classification policy** and map Grond outputs to it.
- For high-sensitivity findings:
  - Limit who can access full reports.
  - Use redaction or summarization where appropriate.
- Consider integrating Grond with:
  - DLP / redaction tools.
  - Case management systems for long-lived investigations.

## Logging and audit

- Enable structured logging and centralize logs.
- Ensure:
  - Tool invocations, including targets and parameters, are logged.
  - Access to admin / authorization endpoints is auditable.
- For larger environments:
  - Use OpenTelemetry to export traces to your observability stack.
  - Build dashboards for:
    - Tool error rates.
    - Active-scan usage.
    - Analyst workload.

---

This playbook is intentionally minimal. Adapt it to your organization’s legal, compliance, and operational requirements.
```

```
        ↓

        ↓

        ↓
6. Semua langkah di-hash → Chain of Custody untuk admissibility di pengadilan
```

## Catatan Khusus untuk Enterprise Readiness

Dari perspektif forensik, ada tiga hal non-negotiable untuk produksi: [^10_1][^10_7][^10_12]

- **Chain of Custody otomatis** — setiap file yang dianalisis harus memiliki hash (SHA-256 minimum, SHA-3 ideal) yang direkam sebelum dan sesudah analisis untuk membuktikan integritas bukti di pengadilan.
- **Isolated execution environment** — tools seperti Steghide dan Binwalk harus dijalankan di container/sandbox terpisah karena payload yang diekstrak **bisa berisi malware**.
- **Encrypted payload storage** — hasil ekstraksi disimpan terenkripsi (AES-256) dengan access control berbasis role, karena payload steganografi sering mengandung materi ilegal atau sangat sensitif. [^10_7]

## 1. Model Pydantic — `src/models/steg_evidence.py`

```python
from __future__ import annotations
from enum import Enum
from typing import Optional
from pydantic import BaseModel, Field
import hashlib
import datetime


class StegConfidence(str, Enum):
    CLEAN = "clean"
    SUSPICIOUS = "suspicious"
    CONFIRMED = "confirmed"
    UNKNOWN = "unknown"


class StegMethod(str, Enum):
    LSB = "lsb"
    F5 = "f5"
    STEGHIDE = "steghide"
    OUTGUESS = "outguess"
    DCT = "dct"
    ARTIFACT_ONLY = "artifact_only"   # Hanya ditemukan bukti instalasi app
    UNKNOWN = "unknown"


class StegAlyzerResult(BaseModel):
    """Model hasil scan dari StegAlyzer Suite (AS, SS, atau RTS)."""

    # Identitas file
    file_path: str
    file_sha256: str
    file_size_bytes: int
    scanned_at: datetime.datetime = Field(
        default_factory=datetime.datetime.utcnow
    )

    # Hasil deteksi
    scanner_type: str                          # "AS", "SS", atau "RTS"
    confidence: StegConfidence
    detected_method: Optional[StegMethod]
    matched_signatures: list[str] = []         # Nama app / signature yang match
    artifact_apps_found: list[str] = []        # Untuk AS: nama app steganografi
    extracted_payload_path: Optional[str]      # Path ke payload (encrypted)

    # Metadata operasional
    tool_version: Optional[str]
    scan_duration_ms: Optional[float]
    raw_output: Optional[str]                  # Output mentah CLI untuk audit

    # Chain of custody (admissibility)
    chain_of_custody_hash: str
    analyst_id: Optional[str]
    authorization_ref: Optional[str]           # Nomor tiket / surat kuasa

    @classmethod
    def compute_coc_hash(
        cls, file_sha256: str, scanned_at: datetime.datetime, scanner_type: str
    ) -> str:
        """Hash CoC untuk admissibility di pengadilan."""
        raw = f"{file_sha256}:{scanned_at.isoformat()}:{scanner_type}"
        return hashlib.sha3_256(raw.encode()).hexdigest()
```

## 2. StegAlyzerAS (Artifact Scanner) — `src/tools/stegalyzer/stegalyzer_as_tool.py`

**StegAlyzerAS** dioperasikan via CLI Windows. Grond memanggil prosesnya via `subprocess` dan mem-parse output XML/teks. [^11_1][^11_3]

```python
"""
StegAlyzerAS Adapter untuk Grond.

StegAlyzerAS adalah tool Windows (GUI + CLI) dari Backbone Security.
Adapter ini menggunakan subprocess untuk menjalankan CLI-nya dan
mem-parse hasilnya menjadi StegAlyzerResult.

Referensi:
  - Mendeteksi 1,025+ aplikasi steganografi via artifact fingerprinting
  - Dijalankan di host Windows atau Windows container
"""

from __future__ import annotations
import subprocess
import asyncio
import datetime
import hashlib
import os
import re
import logging
from pathlib import Path
from typing import Optional

from src.models.steg_evidence import (
    StegAlyzerResult,
    StegConfidence,
    StegMethod,
)

logger = logging.getLogger(__name__)

# Path ke executable StegAlyzerAS CLI
# Harus diset via env var STEGALYZER_AS_PATH
STEGALYZER_AS_EXE = os.environ.get(
    "STEGALYZER_AS_PATH",
    r"C:\Program Files\Backbone Security\StegAlyzerAS\StegAlyzerAS_CLI.exe",
)


def _sha256_file(file_path: str) -> str:
    h = hashlib.sha256()
    with open(file_path, "rb") as f:
        for chunk in iter(lambda: f.read(65536), b""):
            h.update(chunk)
    return h.hexdigest()


def _parse_as_output(raw: str) -> tuple[StegConfidence, list[str]]:
    """
    Parse output teks StegAlyzerAS.
    
    StegAlyzerAS output format (tipikal):
      [FOUND] Application: DeepSound v2.0 — Hash: abc123
      [FOUND] Application: OpenStego 0.8 — Hash: def456
      [CLEAN] No steganography artifacts detected.
    """
    artifacts: list[str] = []
    lines = raw.splitlines()

    for line in lines:
        if "[FOUND]" in line:
            # Ekstrak nama app dari baris
            match = re.search(r"Application:\s*(.+?)\s*[—\-]", line)
            if match:
                artifacts.append(match.group(1).strip())
            else:
                artifacts.append(line.strip())

    confidence = (
        StegConfidence.CONFIRMED if artifacts else StegConfidence.CLEAN
    )
    return confidence, artifacts


async def scan_with_stegalyzer_as(
    file_path: str,
    analyst_id: Optional[str] = None,
    authorization_ref: Optional[str] = None,
    timeout_seconds: int = 120,
) -> StegAlyzerResult:
    """
    Scan file menggunakan StegAlyzerAS (Artifact Scanner).

    Mendeteksi apakah sistem / media penyimpanan pernah
    menggunakan aplikasi steganografi berdasarkan fingerprint hash.

    Args:
        file_path: Path ke file atau direktori yang akan di-scan.
        analyst_id: ID analis yang melakukan scan (untuk CoC).
        authorization_ref: Nomor tiket / surat otorisasi.
        timeout_seconds: Batas waktu eksekusi (default: 120 detik).

    Returns:
        StegAlyzerResult dengan detail temuan.

    Raises:
        FileNotFoundError: Jika executable atau file target tidak ditemukan.
        subprocess.TimeoutExpired: Jika scan melebihi batas waktu.
    """
    if not Path(STEGALYZER_AS_EXE).exists():
        raise FileNotFoundError(
            f"StegAlyzerAS executable tidak ditemukan: {STEGALYZER_AS_EXE}\n"
            f"Set env var STEGALYZER_AS_PATH ke path yang benar."
        )

    if not Path(file_path).exists():
        raise FileNotFoundError(f"File target tidak ditemukan: {file_path}")

    file_sha256 = _sha256_file(file_path)
    file_size = Path(file_path).stat().st_size
    scanned_at = datetime.datetime.utcnow()

    # Jalankan StegAlyzerAS CLI
    cmd = [
        STEGALYZER_AS_EXE,
        "--scan", file_path,
        "--output", "text",     # Format output: text atau xml
        "--verbose",
    ]

    logger.info(
        "Menjalankan StegAlyzerAS",
        extra={"file": file_path, "sha256": file_sha256}
    )

    import time
    start = time.monotonic()

    proc = await asyncio.create_subprocess_exec(
        *cmd,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
    )

    try:
        stdout, stderr = await asyncio.wait_for(
            proc.communicate(), timeout=timeout_seconds
        )
    except asyncio.TimeoutError:
        proc.kill()
        raise subprocess.TimeoutExpired(cmd, timeout_seconds)

    duration_ms = (time.monotonic() - start) * 1000
    raw_output = stdout.decode(errors="replace")

    if proc.returncode not in (0, 1):  # 0=clean, 1=found, lainnya=error
        logger.error(
            "StegAlyzerAS error",
            extra={"returncode": proc.returncode, "stderr": stderr.decode()}
        )

    confidence, artifacts = _parse_as_output(raw_output)

    coc_hash = StegAlyzerResult.compute_coc_hash(
        file_sha256, scanned_at, "AS"
    )

    return StegAlyzerResult(
        file_path=file_path,
        file_sha256=file_sha256,
        file_size_bytes=file_size,
        scanned_at=scanned_at,
        scanner_type="AS",
        confidence=confidence,
        detected_method=StegMethod.ARTIFACT_ONLY if artifacts else None,
        artifact_apps_found=artifacts,
        tool_version="StegAlyzerAS",
        scan_duration_ms=duration_ms,
        raw_output=raw_output,
        chain_of_custody_hash=coc_hash,
        analyst_id=analyst_id,
        authorization_ref=authorization_ref,
    )
```

## 3. StegAlyzerSS (Signature Scanner) — `src/tools/stegalyzer/stegalyzer_ss_tool.py`

**StegAlyzerSS** memindai *isi file* untuk menemukan signature stego yang tersembunyi di dalamnya. [^11_4][^11_1]

```python
"""
StegAlyzerSS Adapter untuk Grond.

StegAlyzerSS memindai file untuk signature byte patterns dari
55+ algoritma steganografi (LSB, F5, Steghide, OutGuess, dll).
Beda dari AS yang mendeteksi keberadaan app, SS mendeteksi
keberadaan DATA tersembunyi di dalam file.
"""

from __future__ import annotations
import subprocess
import asyncio
import datetime
import hashlib
import os
import re
import logging
from pathlib import Path
from typing import Optional

from src.models.steg_evidence import (
    StegAlyzerResult,
    StegConfidence,
    StegMethod,
)

logger = logging.getLogger(__name__)

STEGALYZER_SS_EXE = os.environ.get(
    "STEGALYZER_SS_PATH",
    r"C:\Program Files\Backbone Security\StegAlyzerSS\StegAlyzerSS_CLI.exe",
)

# Mapping nama signature StegAlyzerSS ke enum StegMethod Grond
_SIGNATURE_METHOD_MAP: dict[str, StegMethod] = {
    "lsb": StegMethod.LSB,
    "f5": StegMethod.F5,
    "steghide": StegMethod.STEGHIDE,
    "outguess": StegMethod.OUTGUESS,
    "dct": StegMethod.DCT,
}


def _sha256_file(file_path: str) -> str:
    h = hashlib.sha256()
    with open(file_path, "rb") as f:
        for chunk in iter(lambda: f.read(65536), b""):
            h.update(chunk)
    return h.hexdigest()


def _parse_ss_output(raw: str) -> tuple[StegConfidence, list[str], Optional[StegMethod]]:
    """
    Parse output StegAlyzerSS.

    Tipikal output:
      [SIGNATURE] Method: steghide — Offset: 0x1A4F — Confidence: HIGH
      [SIGNATURE] Method: lsb — Offset: 0x0000 — Confidence: MEDIUM
      [CLEAN] No signatures detected.
    """
    signatures: list[str] = []
    primary_method: Optional[StegMethod] = None
    highest_confidence = StegConfidence.CLEAN

    for line in raw.splitlines():
        if "[SIGNATURE]" in line:
            # Ekstrak nama metode
            method_match = re.search(r"Method:\s*(\w+)", line, re.IGNORECASE)
            confidence_match = re.search(
                r"Confidence:\s*(HIGH|MEDIUM|LOW)", line, re.IGNORECASE
            )

            if method_match:
                method_name = method_match.group(1).lower()
                signatures.append(method_name)
                if primary_method is None:
                    primary_method = _SIGNATURE_METHOD_MAP.get(
                        method_name, StegMethod.UNKNOWN
                    )

            # Tentukan confidence level tertinggi
            if confidence_match:
                level = confidence_match.group(1).upper()
                if level == "HIGH":
                    highest_confidence = StegConfidence.CONFIRMED
                elif level == "MEDIUM" and highest_confidence != StegConfidence.CONFIRMED:
                    highest_confidence = StegConfidence.SUSPICIOUS
                elif level == "LOW" and highest_confidence == StegConfidence.CLEAN:
                    highest_confidence = StegConfidence.SUSPICIOUS

    return highest_confidence, signatures, primary_method


async def scan_with_stegalyzer_ss(
    file_path: str,
    extract_payload: bool = False,
    output_dir: Optional[str] = None,
    analyst_id: Optional[str] = None,
    authorization_ref: Optional[str] = None,
    timeout_seconds: int = 300,
) -> StegAlyzerResult:
    """
    Scan file menggunakan StegAlyzerSS (Signature Scanner).

    Mendeteksi signature steganografi di dalam konten file.
    Opsional: ekstrak payload tersembunyi ke direktori output.

    Args:
        file_path: Path ke file yang akan di-scan (image, audio, dll).
        extract_payload: Jika True, ekstrak payload tersembunyi.
        output_dir: Direktori untuk menyimpan payload yang diekstrak.
        analyst_id: ID analis untuk Chain of Custody.
        authorization_ref: Referensi otorisasi.
        timeout_seconds: Batas waktu eksekusi.

    PERINGATAN KEAMANAN:
        Payload yang diekstrak bisa berisi malware.
        Selalu jalankan di sandbox / container terisolasi.
        Pastikan output_dir di-mount dari luar container.
    """
    if not Path(STEGALYZER_SS_EXE).exists():
        raise FileNotFoundError(
            f"StegAlyzerSS tidak ditemukan: {STEGALYZER_SS_EXE}"
        )

    file_sha256 = _sha256_file(file_path)
    file_size = Path(file_path).stat().st_size
    scanned_at = datetime.datetime.utcnow()

    cmd = [
        STEGALYZER_SS_EXE,
        "--scan", file_path,
        "--output", "text",
        "--verbose",
    ]

    # Tambahkan flag ekstraksi jika diminta dan ada otorisasi
    extracted_payload_path: Optional[str] = None
    if extract_payload:
        if not authorization_ref:
            raise PermissionError(
                "Ekstraksi payload memerlukan authorization_ref yang valid. "
                "Sertakan nomor tiket / surat kuasa sebelum ekstraksi."
            )
        if not output_dir:
            raise ValueError("output_dir diperlukan saat extract_payload=True")
        Path(output_dir).mkdir(parents=True, exist_ok=True)
        cmd.extend(["--extract", "--output-dir", output_dir])
        extracted_payload_path = output_dir

    import time
    start = time.monotonic()

    proc = await asyncio.create_subprocess_exec(
        *cmd,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
    )

    try:
        stdout, stderr = await asyncio.wait_for(
            proc.communicate(), timeout=timeout_seconds
        )
    except asyncio.TimeoutError:
        proc.kill()
        raise subprocess.TimeoutExpired(cmd, timeout_seconds)

    duration_ms = (time.monotonic() - start) * 1000
    raw_output = stdout.decode(errors="replace")

    confidence, signatures, primary_method = _parse_ss_output(raw_output)

    logger.info(
        "StegAlyzerSS selesai",
        extra={
            "file": file_path,
            "confidence": confidence,
            "signatures": signatures,
        }
    )

    coc_hash = StegAlyzerResult.compute_coc_hash(
        file_sha256, scanned_at, "SS"
    )

    return StegAlyzerResult(
        file_path=file_path,
        file_sha256=file_sha256,
        file_size_bytes=file_size,
        scanned_at=scanned_at,
        scanner_type="SS",
        confidence=confidence,
        detected_method=primary_method,
        matched_signatures=signatures,
        extracted_payload_path=extracted_payload_path,
        tool_version="StegAlyzerSS",
        scan_duration_ms=duration_ms,
        raw_output=raw_output,
        chain_of_custody_hash=coc_hash,
        analyst_id=analyst_id,
        authorization_ref=authorization_ref,
    )
```

## 4. StegAlyzerRTS Client — `src/tools/stegalyzer/stegalyzer_rts_client.py`

**StegAlyzerRTS** adalah network appliance yang mendeteksi steganografi di traffic *real-time*. [^11_1][^11_2] Grond terhubung ke RTS via API/webhook untuk menerima alert.

```python
"""
StegAlyzerRTS Client untuk Grond.

StegAlyzerRTS adalah network security appliance yang memonitor
traffic secara real-time untuk mendeteksi steganografi in-transit.
Adapter ini bertindak sebagai consumer dari alert yang dikirim RTS
ke Grond via webhook atau polling.

Kapabilitas RTS:
  - Deteksi fingerprint 1,150+ stego apps
  - Deteksi signature 55+ stego apps in real-time
  - Automated Extraction Algorithm untuk selected apps
"""

from __future__ import annotations
import asyncio
import datetime
import logging
import os
from typing import Optional, Callable, Awaitable
import httpx
from pydantic import BaseModel

logger = logging.getLogger(__name__)

# Endpoint API StegAlyzerRTS (dikonfigurasi via env)
RTS_API_BASE = os.environ.get("STEGALYZER_RTS_URL", "http://rts-appliance:8080")
RTS_API_KEY = os.environ.get("STEGALYZER_RTS_API_KEY", "")


class RTSAlert(BaseModel):
    """Model alert dari StegAlyzerRTS."""
    alert_id: str
    timestamp: datetime.datetime
    source_ip: str
    destination_ip: str
    protocol: str                  # HTTP, SMTP, FTP, dll.
    file_name: Optional[str]
    file_sha256: Optional[str]
    detected_method: Optional[str]
    confidence: str                # HIGH, MEDIUM, LOW
    action_taken: Optional[str]    # BLOCKED, ALERTED, QUARANTINED
    raw_payload_ref: Optional[str] # Referensi ke file di RTS storage


class StegAlyzerRTSClient:
    """
    Client untuk StegAlyzerRTS Network Appliance.
    
    Mendukung dua mode:
    1. Polling: Grond secara periodik fetch alert baru dari RTS API.
    2. Webhook: RTS push alert ke endpoint Grond (direkomendasikan).
    """

    def __init__(
        self,
        base_url: str = RTS_API_BASE,
        api_key: str = RTS_API_KEY,
        timeout_seconds: int = 30,
    ):
        self.base_url = base_url.rstrip("/")
        self.headers = {
            "X-API-Key": api_key,
            "Content-Type": "application/json",
        }
        self.timeout = timeout_seconds
        self._alert_handlers: list[Callable[[RTSAlert], Awaitable[None]]] = []

    def register_alert_handler(
        self, handler: Callable[[RTSAlert], Awaitable[None]]
    ) -> None:
        """Daftarkan handler async yang dipanggil saat ada alert baru."""
        self._alert_handlers.append(handler)

    async def fetch_recent_alerts(
        self,
        since: Optional[datetime.datetime] = None,
        limit: int = 100,
    ) -> list[RTSAlert]:
        """
        Fetch alert terbaru dari StegAlyzerRTS via polling.
        
        Gunakan mode ini saat webhook tidak tersedia.
        """
        params: dict = {"limit": limit}
        if since:
            params["since"] = since.isoformat()

        async with httpx.AsyncClient(
            headers=self.headers, timeout=self.timeout
        ) as client:
            response = await client.get(
                f"{self.base_url}/api/v1/alerts",
                params=params,
            )
            response.raise_for_status()
            data = response.json()

        alerts = [RTSAlert(**item) for item in data.get("alerts", [])]
        logger.info(
            "Fetched RTS alerts",
            extra={"count": len(alerts)}
        )
        return alerts

    async def poll_loop(
        self,
        interval_seconds: int = 60,
        lookback_minutes: int = 5,
    ) -> None:
        """
        Loop polling continuous — fetch alert setiap interval_seconds.
        
        Untuk production, lebih disarankan menggunakan webhook.
        """
        logger.info(
            "Memulai RTS polling loop",
            extra={"interval_seconds": interval_seconds}
        )
        while True:
            since = datetime.datetime.utcnow() - datetime.timedelta(
                minutes=lookback_minutes
            )
            try:
                alerts = await self.fetch_recent_alerts(since=since)
                for alert in alerts:
                    for handler in self._alert_handlers:
                        await handler(alert)
            except Exception as exc:
                logger.error(
                    "RTS polling error",
                    extra={"error": str(exc)}
                )
            await asyncio.sleep(interval_seconds)

    async def process_webhook_payload(
        self, payload: dict
    ) -> Optional[RTSAlert]:
        """
        Proses payload webhook dari StegAlyzerRTS.
        
        Daftarkan endpoint ini di FastAPI:
          POST /api/v1/integrations/stegalyzer-rts/webhook
        """
        try:
            alert = RTSAlert(**payload)
            for handler in self._alert_handlers:
                await handler(alert)
            logger.info(
                "RTS webhook alert diproses",
                extra={"alert_id": alert.alert_id}
            )
            return alert
        except Exception as exc:
            logger.error(
                "Gagal memproses RTS webhook",
                extra={"error": str(exc), "payload": payload}
            )
            return None

    async def quarantine_file(self, alert_id: str) -> bool:
        """
        Perintahkan RTS untuk mengkarantina file terkait alert.
        Hanya tersedia jika RTS dikonfigurasi dengan mode ACTIVE.
        """
        async with httpx.AsyncClient(
            headers=self.headers, timeout=self.timeout
        ) as client:
            response = await client.post(
                f"{self.base_url}/api/v1/alerts/{alert_id}/quarantine"
            )
            return response.status_code == 200
```

```python
from src.tools.stegalyzer.stegalyzer_rts_client import (

RTS_WEBHOOK_SECRET = os.environ.get("STEGALYZER_RTS_WEBHOOK_SECRET", "")

@router.post("/stegalyzer-rts/webhook")
async def stegalyzer_rts_webhook(
    request: Request,
    x_rts_signature: str = Header(None),
):
    """
    Endpoint webhook untuk menerima alert real-time dari StegAlyzerRTS.
    
    StegAlyzerRTS dikonfigurasi untuk POST ke URL ini setiap ada deteksi.
    Setiap alert diverifikasi signature dan dicatat ke audit log.
    """
    # Verifikasi signature webhook dari RTS
    if not _verify_rts_signature(x_rts_signature, await request.body()):
        raise HTTPException(status_code=401, detail="Invalid RTS webhook signature")

    payload = await request.json()

    alert = await rts_client.process_webhook_payload(payload)
    if not alert:
        raise HTTPException(status_code=422, detail="Invalid alert payload")

    # Catat ke audit log Grond
    await log_audit_event(
        event_type="stegalyzer_rts_alert",
        details={
            "alert_id": alert.alert_id,
            "source_ip": alert.source_ip,
            "confidence": alert.confidence,
            "detected_method": alert.detected_method,
        }
    )

    return {"status": "received", "alert_id": alert.alert_id}


def _verify_rts_signature(signature: str, body: bytes) -> bool:
    """Verifikasi HMAC-SHA256 signature dari RTS webhook."""
    import hmac, hashlib
    if not RTS_WEBHOOK_SECRET:
        return True  # Skip di development tanpa secret
    expected = hmac.new(
        RTS_WEBHOOK_SECRET.encode(), body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(signature or "", expected)
```

## 6. Orchestrator di Visual Forensics Pipeline

```python
# src/pipeline/visual_forensics.py (penambahan ke file yang sudah ada)

from src.tools.stegalyzer.stegalyzer_as_tool import scan_with_stegalyzer_as
from src.tools.stegalyzer.stegalyzer_ss_tool import scan_with_stegalyzer_ss

async def run_stegalyzer_suite(
    file_path: str,
    analyst_id: str,
    authorization_ref: str,
    run_as: bool = True,
    run_ss: bool = True,
    extract_if_confirmed: bool = False,
    payload_output_dir: str = "/secure/payloads",
) -> dict:
    """
    Jalankan StegAlyzerAS + SS secara paralel pada satu file.
    
    Alur:
    1. AS + SS berjalan paralel (asyncio.gather)
    2. Jika SS konfirmasi CONFIRMED + extract_if_confirmed=True 
       → re-run SS dengan ekstraksi
    3. Semua hasil dikembalikan sebagai dict untuk IntelReport
    """
    tasks = []
    if run_as:
        tasks.append(scan_with_stegalyzer_as(
            file_path, analyst_id=analyst_id,
            authorization_ref=authorization_ref
        ))
    if run_ss:
        tasks.append(scan_with_stegalyzer_ss(
            file_path, analyst_id=analyst_id,
            authorization_ref=authorization_ref
        ))

    results = await asyncio.gather(*tasks, return_exceptions=True)

    # Re-run SS dengan ekstraksi jika ada konfirmasi kuat
    ss_result = results[^11_1] if run_ss and len(results) > 1 else None
    if (
        extract_if_confirmed
        and ss_result
        and not isinstance(ss_result, Exception)
        and ss_result.confidence == "confirmed"
    ):
        ss_result = await scan_with_stegalyzer_ss(
            file_path,
            extract_payload=True,
            output_dir=payload_output_dir,
            analyst_id=analyst_id,
            authorization_ref=authorization_ref,
        )

    return {
        "as_result": results[^11_0] if run_as else None,
        "ss_result": ss_result,
    }
```

```python
from enum import Enum
from typing import Optional
from datetime import datetime
from pydantic import BaseModel, Field
import hashlib
import os


class StegAlyzerComponent(str, Enum):
    AS = "StegAlyzerAS"   # Artifact Scanner

class StegDetectionResult(str, Enum):
    CLEAN = "clean"
    ARTIFACT_FOUND = "artifact_found"   # AS: stego tool artifact ditemukan
    SIGNATURE_FOUND = "signature_found" # SS: stego signature ditemukan di file
    PAYLOAD_EXTRACTED = "payload_extracted"
    ERROR = "error"

    file_path: str
    file_sha256: str
    file_size_bytes: int
    source_url: Optional[str] = None

    # Hasil analisis
    component: StegAlyzerComponent
    result: StegDetectionResult
    confidence_score: Optional[float] = Field(None, ge=0.0, le=1.0)

    detected_signature: Optional[str] = None  # Nama signature (SS)
    extracted_payload_path: Optional[str] = None  # Path ke payload terenkripsi

    analyst_workstation: str
    chain_of_custody_hash: str  # Hash dari (file_sha256 + timestamp + analyst)
    raw_report_path: Optional[str] = None  # Path ke laporan CSV/TXT mentah
    tool_version: Optional[str] = None
    notes: Optional[str] = None

    @classmethod
    def compute_coc_hash(
        cls,
        file_sha256: str,
        timestamp: datetime,
        analyst: str
    ) -> str:
        """Buat chain-of-custody hash untuk admissibility di pengadilan."""
        raw = f"{file_sha256}|{timestamp.isoformat()}|{analyst}"
```

## 2. `src/tools/stegalyzer_as_tool.py` — Artifact Scanner

StegAlyzerAS mendeteksi keberadaan **aplikasi steganografi** di sistem target dengan membandingkan hash file terhadap database 1.025+ aplikasi stego. [^12_1][^12_5] Ini menjawab pertanyaan: *"Apakah subjek pernah menggunakan tool steganografi?"*

```python
"""
StegAlyzerAS (Artifact Scanner) tool adapter untuk Grond.
Mendeteksi artefak dari 1.025+ aplikasi steganografi via hash comparison.

Prerequisite:
  - StegAlyzerAS terinstall di host (Windows binary atau Wine wrapper di Linux).
  - Path ke executable dikonfigurasi via env: STEGALYZER_AS_PATH
  - SARC database terupdate: STEGALYZER_DB_PATH
"""

import subprocess
import os
import csv
import hashlib
import asyncio
from datetime import datetime
from pathlib import Path
from typing import Optional

from src.models.stegalyzer_evidence import (
    StegAlyzerEvidence,
    StegAlyzerComponent,
    StegDetectionResult,
)
from src.core.settings import settings
from src.core.audit import audit_log


STEGALYZER_AS_PATH = os.getenv("STEGALYZER_AS_PATH", "/opt/stegalyzer/StegAlyzerAS.exe")
STEGALYZER_DB_PATH = os.getenv("STEGALYZER_DB_PATH", "/opt/stegalyzer/sarc_db")
REPORT_OUTPUT_DIR = Path(os.getenv("STEG_REPORT_DIR", "/tmp/grond_steg_reports"))
REPORT_OUTPUT_DIR.mkdir(parents=True, exist_ok=True)


def _sha256_file(path: str) -> str:
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(65536), b""):
            h.update(chunk)
    return h.hexdigest()


def _parse_as_report(report_csv: str) -> tuple[StegDetectionResult, Optional[str]]:
    """
    Parse output CSV StegAlyzerAS.
    Format kolom: Filename, HashMatch, AppName, AppVersion, Risk
    """
    try:
        with open(report_csv, newline="", encoding="utf-8-sig") as f:
            reader = csv.DictReader(f)
            for row in reader:
                if row.get("HashMatch", "").strip().upper() == "YES":
                    app_name = row.get("AppName", "Unknown").strip()
                    return StegDetectionResult.ARTIFACT_FOUND, app_name
        return StegDetectionResult.CLEAN, None
    except Exception as e:
        return StegDetectionResult.ERROR, str(e)


async def run_stegalyzer_as(
    target_path: str,
    analyst_id: str,
    source_url: Optional[str] = None,
) -> StegAlyzerEvidence:
    """
    Jalankan StegAlyzerAS terhadap file atau direktori target.

    Args:
        target_path: Path absolut ke file atau direktori yang akan di-scan.
        analyst_id: ID analis yang memicu scan (untuk audit trail).
        source_url: URL asal file (jika dikumpulkan dari internet).

    Returns:
        StegAlyzerEvidence yang siap masuk ke IntelReport.
    """
    target = Path(target_path)
    if not target.exists():
        raise FileNotFoundError(f"Target tidak ditemukan: {target_path}")

    ts = datetime.utcnow()
    report_path = REPORT_OUTPUT_DIR / f"as_report_{ts.strftime('%Y%m%d_%H%M%S')}.csv"
    file_sha256 = _sha256_file(target_path) if target.is_file() else "DIRECTORY"
    file_size = target.stat().st_size if target.is_file() else 0

    # Audit: catat setiap invokasi sebelum eksekusi
    await audit_log(
        action="stegalyzer_as_scan",
        actor=analyst_id,
        target=target_path,
        metadata={
            "sha256": file_sha256,
            "source_url": source_url,
            "report_output": str(report_path),
        }
    )

    # Bangun command StegAlyzerAS (CLI mode)
    # Referensi: SARC Products and Services brochure + forensic usage docs
    cmd = [
        STEGALYZER_AS_PATH,
        "--scan", str(target),
        "--db", STEGALYZER_DB_PATH,
        "--output", str(report_path),
        "--format", "csv",
        "--silent",
    ]

    try:
        proc = await asyncio.create_subprocess_exec(
            *cmd,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE,
        )
        stdout, stderr = await asyncio.wait_for(proc.communicate(), timeout=120)

        if proc.returncode not in (0, 1):
            # StegAlyzerAS returns 1 jika artifact ditemukan (bukan error)
            raise RuntimeError(
                f"StegAlyzerAS keluar dengan kode {proc.returncode}: "
                f"{stderr.decode(errors='replace')}"
            )
    except asyncio.TimeoutError:
        proc.kill()
        raise TimeoutError(f"StegAlyzerAS timeout pada target: {target_path}")

    # Parse hasil
    result, detected_app = _parse_as_report(str(report_path))
    coc_hash = StegAlyzerEvidence.compute_coc_hash(file_sha256, ts, analyst_id)

    evidence = StegAlyzerEvidence(
        file_path=str(target),
        file_sha256=file_sha256,
        file_size_bytes=file_size,
        source_url=source_url,
        component=StegAlyzerComponent.AS,
        result=result,
        detected_app=detected_app,
        analysis_timestamp=ts,
        analyst_workstation=settings.hostname,
        chain_of_custody_hash=coc_hash,
        raw_report_path=str(report_path),
        notes=stdout.decode(errors="replace") if stdout else None,
    )

    return evidence
```

## 3. `src/tools/stegalyzer_ss_tool.py` — Signature Scanner + Payload Extraction

StegAlyzerSS mendeteksi **signature steganografi di dalam file** dan menyediakan kemampuan *point-click-extract* untuk mengekstrak payload tersembunyi. [^12_1][^12_2] Ini menjawab: *"Apakah file ini menyembunyikan data?"*

```python
"""
StegAlyzerSS (Signature Scanner) tool adapter untuk Grond.
Deteksi steganographic signatures di dalam file + payload extraction.

Env:
  STEGALYZER_SS_PATH: Path ke executable StegAlyzerSS
  STEG_PAYLOAD_DIR:   Dir terenkripsi untuk menyimpan payload hasil ekstraksi
"""

import subprocess
import os
import asyncio
import hashlib
from datetime import datetime
from pathlib import Path
from typing import Optional
import json

from cryptography.fernet import Fernet

from src.models.stegalyzer_evidence import (
    StegAlyzerEvidence,
    StegAlyzerComponent,
    StegDetectionResult,
)
from src.core.settings import settings
from src.core.audit import audit_log


STEGALYZER_SS_PATH = os.getenv("STEGALYZER_SS_PATH", "/opt/stegalyzer/StegAlyzerSS.exe")
PAYLOAD_DIR = Path(os.getenv("STEG_PAYLOAD_DIR", "/secure/grond_payloads"))
PAYLOAD_DIR.mkdir(parents=True, exist_ok=True, mode=0o700)  # hanya owner

# Encryption key untuk payload — harus dari secrets manager di production
PAYLOAD_ENCRYPTION_KEY = os.getenv("STEG_PAYLOAD_KEY", Fernet.generate_key())
_fernet = Fernet(PAYLOAD_ENCRYPTION_KEY)


def _encrypt_and_store_payload(raw_payload_path: str, file_sha256: str) -> str:
    """Enkripsi payload hasil ekstraksi sebelum disimpan (AES-128-CBC via Fernet)."""
    with open(raw_payload_path, "rb") as f:
        raw = f.read()
    encrypted = _fernet.encrypt(raw)
    dest = PAYLOAD_DIR / f"{file_sha256[:16]}_payload.enc"
    with open(dest, "wb") as f:
        f.write(encrypted)
    os.remove(raw_payload_path)  # Hapus plaintext
    return str(dest)


def _parse_ss_output(stdout: str) -> tuple[StegDetectionResult, Optional[str], Optional[float]]:
    """
    Parse stdout StegAlyzerSS.
    StegAlyzerSS biasanya output: SIGNATURE FOUND: <name> (confidence: X%)
    """
    lines = stdout.lower().splitlines()
    for line in lines:
        if "signature found" in line:
            parts = line.split(":")
            sig_name = parts[^12_1].strip().split("(")[^12_0].strip() if len(parts) > 1 else "unknown"
            # Ekstrak confidence jika ada
            confidence = None
            if "confidence" in line and "%" in line:
                try:
                    conf_str = line.split("confidence:")[-1].replace("%", "").strip()
                    confidence = float(conf_str) / 100.0
                except (ValueError, IndexError):
                    pass
            return StegDetectionResult.SIGNATURE_FOUND, sig_name, confidence
    return StegDetectionResult.CLEAN, None, None


async def run_stegalyzer_ss(
    file_path: str,
    analyst_id: str,
    extract_payload: bool = False,
    source_url: Optional[str] = None,
) -> StegAlyzerEvidence:
    """
    Jalankan StegAlyzerSS untuk deteksi signature + opsional ekstraksi payload.

    Args:
        file_path: Path ke file yang akan di-scan.
        analyst_id: ID analis (audit trail).
        extract_payload: Jika True, ekstrak dan enkripsi payload tersembunyi.
        source_url: URL asal file.

    PERINGATAN KEAMANAN:
        extract_payload=True hanya boleh dijalankan di sandbox/container terisolasi.
        Payload yang diekstrak bisa mengandung malware atau konten ilegal.
    """
    target = Path(file_path)
    if not target.exists():
        raise FileNotFoundError(f"File tidak ditemukan: {file_path}")

    ts = datetime.utcnow()
    file_sha256 = _compute_sha256(file_path)

    await audit_log(
        action="stegalyzer_ss_scan",
        actor=analyst_id,
        target=file_path,
        metadata={
            "sha256": file_sha256,
            "extract_payload": extract_payload,
            "source_url": source_url,
        }
    )

    # Tentukan raw payload output path
    raw_payload_path = str(PAYLOAD_DIR / f"{file_sha256[:16]}_raw.bin")

    cmd = [
        STEGALYZER_SS_PATH,
        "--file", str(target),
        "--silent",
    ]

    if extract_payload:
        cmd += ["--extract", "--output", raw_payload_path]

    try:
        proc = await asyncio.create_subprocess_exec(
            *cmd,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE,
        )
        stdout, stderr = await asyncio.wait_for(proc.communicate(), timeout=180)
    except asyncio.TimeoutError:
        proc.kill()
        raise TimeoutError(f"StegAlyzerSS timeout: {file_path}")

    stdout_text = stdout.decode(errors="replace")
    result, detected_sig, confidence = _parse_ss_output(stdout_text)

    # Simpan dan enkripsi payload jika diekstrak
    payload_stored_path = None
    if extract_payload and os.path.exists(raw_payload_path):
        payload_stored_path = _encrypt_and_store_payload(raw_payload_path, file_sha256)
        result = StegDetectionResult.PAYLOAD_EXTRACTED

    coc_hash = StegAlyzerEvidence.compute_coc_hash(file_sha256, ts, analyst_id)

    return StegAlyzerEvidence(
        file_path=str(target),
        file_sha256=file_sha256,
        file_size_bytes=target.stat().st_size,
        source_url=source_url,
        component=StegAlyzerComponent.SS,
        result=result,
        confidence_score=confidence,
        detected_signature=detected_sig,
        extracted_payload_path=payload_stored_path,
        analysis_timestamp=ts,
        analyst_workstation=settings.hostname,
        chain_of_custody_hash=coc_hash,
        notes=stdout_text,
    )


def _compute_sha256(path: str) -> str:
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(65536), b""):
            h.update(chunk)
    return h.hexdigest()
```

## 4. `src/tools/stegalyzer_rts_tool.py` — Real-Time Scanner (Network)

StegAlyzerRTS adalah **network security appliance** yang mendeteksi steganografi di network traffic stream secara real-time — satu-satunya produk komersial yang mampu melakukan ini. [^12_4][^12_3] Di Grond, ini diintegrasikan sebagai **webhook receiver** yang menerima alert dari appliance RTS.

```python
"""
StegAlyzerRTS integration untuk Grond.
StegAlyzerRTS beroperasi sebagai network appliance terpisah.
Integrasi dilakukan via webhook/syslog: appliance mengirim alert ke Grond API.

Mode deployment:
  - RTS appliance (Ribcage) → syslog/HTTP POST → Grond /api/v1/steg/rts-alert
  - Grond menerima, memvalidasi, dan memasukkan ke pipeline sebagai evidence.
"""

from fastapi import APIRouter, HTTPException, Header, Request
from pydantic import BaseModel
from typing import Optional
from datetime import datetime
import hmac
import hashlib

from src.models.stegalyzer_evidence import (
    StegAlyzerEvidence,
    StegAlyzerComponent,
    StegDetectionResult,
)
from src.core.audit import audit_log
from src.core.settings import settings


router = APIRouter(prefix="/api/v1/steg", tags=["steganography"])

RTS_WEBHOOK_SECRET = settings.stegalyzer_rts_webhook_secret  # Dari .env


class RTSAlertPayload(BaseModel):
    """
    Payload yang dikirim StegAlyzerRTS ke Grond saat mendeteksi stego di traffic.
    Format disesuaikan dengan output RTS alert stream.
    """
    alert_id: str
    timestamp: datetime
    src_ip: str
    dst_ip: str
    protocol: str            # HTTP, FTP, SMTP, dll.
    filename: Optional[str]
    file_sha256: Optional[str]
    detected_app: Optional[str]
    confidence: Optional[float]
    raw_log: Optional[str]


def _verify_rts_signature(body: bytes, signature: str) -> bool:
    """Verifikasi HMAC-SHA256 dari RTS appliance untuk mencegah spoofing."""
    expected = hmac.new(
        RTS_WEBHOOK_SECRET.encode(),
        body,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, signature)


@router.post("/rts-alert")
async def receive_rts_alert(
    request: Request,
    payload: RTSAlertPayload,
    x_rts_signature: Optional[str] = Header(None),
):
    """
    Endpoint untuk menerima alert dari StegAlyzerRTS appliance.
    RTS dikonfigurasi untuk POST ke URL ini setiap kali mendeteksi stego.
    """
    # Verifikasi signature dari RTS appliance
    body = await request.body()
    if not x_rts_signature or not _verify_rts_signature(body, x_rts_signature):
        raise HTTPException(status_code=401, detail="Invalid RTS signature")

    # Buat evidence record
    coc_hash = StegAlyzerEvidence.compute_coc_hash(
        file_sha256=payload.file_sha256 or payload.alert_id,
        timestamp=payload.timestamp,
        analyst="rts_appliance_auto",
    )

    evidence = StegAlyzerEvidence(
        file_path=payload.filename or f"network_capture_{payload.alert_id}",
        file_sha256=payload.file_sha256 or "N/A",
        file_size_bytes=0,
        source_url=f"network://{payload.src_ip}->{payload.dst_ip}/{payload.protocol}",
        component=StegAlyzerComponent.RTS,
        result=StegDetectionResult.SIGNATURE_FOUND,
        confidence_score=payload.confidence,
        detected_app=payload.detected_app,
        analysis_timestamp=payload.timestamp,
        analyst_workstation="rts_appliance",
        chain_of_custody_hash=coc_hash,
        notes=payload.raw_log,
    )

    # Audit log
    await audit_log(
        action="rts_alert_received",
        actor="stegalyzer_rts",
        target=payload.filename or payload.alert_id,
        metadata={
            "src_ip": payload.src_ip,
            "dst_ip": payload.dst_ip,
            "detected_app": payload.detected_app,
            "alert_id": payload.alert_id,
        }
    )

    # Masukkan ke pipeline Grond untuk enrichment dan reporting
    from src.pipeline.visual_forensics import enqueue_steg_evidence
    await enqueue_steg_evidence(evidence)

    return {"status": "accepted", "alert_id": payload.alert_id}
```

## 5. `src/pipeline/visual_forensics.py` — Orchestrator Pipeline Stage

Stage baru ini mengorkestrasikan semua tools steg dalam satu titik di pipeline Grond:

```python
"""
Visual Forensics pipeline stage.
Disisipkan antara Enrich dan Verify dalam pipeline Grond.

Alur:
  Media asset (gambar/file) → AS scan → SS scan (jika perlu) → evidence
"""

import asyncio
from typing import List
from pathlib import Path

from src.models.stegalyzer_evidence import StegAlyzerEvidence, StegDetectionResult
from src.tools.stegalyzer_as_tool import run_stegalyzer_as
from src.tools.stegalyzer_ss_tool import run_stegalyzer_ss
from src.core.settings import settings
import structlog

logger = structlog.get_logger(__name__)

# Buffer untuk RTS alerts yang masuk real-time
_rts_evidence_queue: asyncio.Queue = asyncio.Queue()


async def enqueue_steg_evidence(evidence: StegAlyzerEvidence):
    """Dipanggil oleh RTS webhook endpoint untuk memasukkan evidence ke queue."""
    await _rts_evidence_queue.put(evidence)


async def analyze_media_assets(
    asset_paths: List[str],
    analyst_id: str,
    source_urls: dict = None,
    extract_on_detection: bool = False,
) -> List[StegAlyzerEvidence]:
    """
    Proses list file media melalui pipeline steganalysis:
    1. AS scan (artifact detection) — cepat, semua file
    2. Jika AS flagging → SS scan (signature detection) — dalam
    3. Jika SS confirms → opsional payload extraction (dengan flag eksplisit)

    Args:
        asset_paths: List path file yang akan dianalisis.
        analyst_id: ID analis untuk audit trail.
        source_urls: Dict {path: url} untuk provenance.
        extract_on_detection: Hanya True jika analis memiliki otorisasi
                               dan sandbox sudah disiapkan.
    """
    source_urls = source_urls or {}
    results: List[StegAlyzerEvidence] = []

    # Fase 1: AS scan — parallel untuk semua file
    logger.info("visual_forensics.as_scan_start", count=len(asset_paths))
    as_tasks = [
        run_stegalyzer_as(
            target_path=path,
            analyst_id=analyst_id,
            source_url=source_urls.get(path),
        )
        for path in asset_paths
    ]
    as_results = await asyncio.gather(*as_tasks, return_exceptions=True)

    # Fase 2: SS scan hanya untuk file yang di-flag AS
    flagged_paths = []
    for path, result in zip(asset_paths, as_results):
        if isinstance(result, Exception):
            logger.error("visual_forensics.as_error", path=path, error=str(result))
            continue
        results.append(result)
        if result.result == StegDetectionResult.ARTIFACT_FOUND:
            flagged_paths.append(path)

    if flagged_paths:
        logger.warning(
            "visual_forensics.artifacts_detected",
            count=len(flagged_paths),
            paths=flagged_paths,
        )
        ss_tasks = [
            run_stegalyzer_ss(
                file_path=path,
                analyst_id=analyst_id,
                extract_payload=extract_on_detection,
                source_url=source_urls.get(path),
            )
            for path in flagged_paths
        ]
        ss_results = await asyncio.gather(*ss_tasks, return_exceptions=True)
        for result in ss_results:
            if not isinstance(result, Exception):
                results.append(result)
            else:
                logger.error("visual_forensics.ss_error", error=str(result))

    return results
```

## Catatan Forensik Kritis

Tiga hal yang tidak boleh diabaikan sebelum deploy ke production:[^12_6][^12_4][^12_1]

- **Isolated sandbox wajib** untuk StegAlyzerSS dengan `extract_on_detection=True` — payload yang diekstrak bisa berisi malware aktif atau konten CSAM yang secara hukum berbeda penanganannya.

- **Chain-of-custody hash** yang dihasilkan `compute_coc_hash()` harus disimpan di append-only audit log yang tidak bisa dimodifikasi — ini yang membuat evidence admissible di pengadilan.

## Apa itu Git Worktree \& Mengapa Penting untuk Grond

Git worktree memungkinkan satu repository memiliki **beberapa working directory aktif sekaligus**, masing-masing di branch berbeda, tanpa perlu `git stash` atau clone ulang. [^13_1][^13_2] Untuk Grond yang memiliki banyak komponen paralel (Python backend, TS orchestration, Next.js dashboard, stegalyzer tools), ini sangat ideal karena Anda bisa mengerjakan:

- Feature baru di `feat/phone-osint` tanpa mengganggu `feat/stegalyzer-integration` yang sedang berjalan
- Bug fix darurat di `main` tanpa harus menutup pekerjaan yang sedang berlangsung
- Setiap Claude Code agent berjalan di worktree isolasi masing-masing [^13_3][^13_4]

# apa yg perlu di optimisasi dari project ini? breakdown!

Langsung ke inti, berdasarkan seluruh analisis repo Grond yang sudah kita lakukan dari sesi ini — berikut breakdown komprehensif area optimasi dari perspektif **Senior Forensic Investigator + Software Architect**.

***

## 🔴 CRITICAL — Harus Dioptimasi Sebelum Production

### 1. Pipeline Tidak Ada Feedback Loop Otomatis

Grond menjalankan `collect → enrich → verify → report` **secara linear satu arah**.  Tidak ada mekanisme:

- **Retry dengan strategi berbeda** kalau satu tool gagal (misal Shodan timeout → fallback ke Censys)
- **Re-collect** kalau hasil enrichment confidence-nya terlalu rendah
- **Loop kembali ke collect** kalau verifier menemukan kontradiksi antar sumber

**Optimasi yang dibutuhkan:**

```
collect → enrich → verify
              ↑          ↓ (jika confidence < threshold)
              └──── re-collect dengan expanded scope
```

Implementasi: tambah `confidence_threshold` di `src/core/orchestrator.py` dan wire ke LangGraph conditional edge.

***

### 2. Tidak Ada Rate Limiting \& Backpressure di Tool Layer

Semua tool adapter di `src/tools/` dipanggil async secara paralel tanpa kontrol beban.  Pada volume enterprise (ratusan target OSINT sekaligus), ini akan:

- **Memicu ban API** dari Shodan, Tavily, Twitter karena rate limit dilanggar
- **Membanjiri Redis queue** tanpa backpressure
- **Memory leak** dari terlalu banyak coroutine yang berjalan serentak

**Optimasi yang dibutuhkan:**

```python
# src/core/rate_limiter.py — belum ada di Grond saat ini
from asyncio import Semaphore

TOOL_CONCURRENCY = {
    "shodan": Semaphore(5),      # max 5 concurrent requests
    "tavily": Semaphore(10),
    "twitter": Semaphore(3),
}
```


***

### 3. Error Handling di Pipeline Masih Generik

Grond belum memiliki pola **granular error taxonomy** yang eksplisit di pipeline.  Dalam konteks forensik ini sangat berbahaya karena:

- Error dari **tool network timeout** diperlakukan sama seperti **tool mengembalikan data kosong yang valid**
- Report bisa dihasilkan dari data parsial tanpa flag yang jelas
- Analis tidak tahu apakah laporan **complete** atau **degraded**

**Optimasi yang dibutuhkan:**


| Error Class | Contoh | Handling |
| :-- | :-- | :-- |
| `ToolTimeoutError` | Shodan tidak merespons | Retry 3x → fallback tool → flag laporan |
| `ToolRateLimitError` | Twitter 429 | Backoff eksponensial → queue ulang |
| `EmptyResultError` | Target tidak ditemukan | Catat sebagai bukti negatif valid |
| `AuthorizationError` | Target belum diotorisasi | Hard stop + audit log |
| `PartialResultError` | 3 dari 5 tool berhasil | Lanjut dengan degraded flag di report |


***

## 🟠 HIGH — Penting untuk Keandalan Enterprise

### 4. Database Schema Belum Dioptimasi untuk Query OSINT

Grond pakai PostgreSQL + pgvector, tapi tidak ada petunjuk index strategy di dokumentasi maupun migration file.  Untuk query OSINT enterprise yang umum:

- Cari semua evidence terkait satu domain/IP **→ butuh GIN index** pada JSONB field
- Vector similarity search untuk duplicate detection **→ butuh HNSW index** di pgvector, bukan flat index default
- Time-range query pada `analysis_timestamp` **→ butuh BRIN index** untuk append-heavy time series

**Optimasi yang dibutuhkan:**

```sql
-- Tambahkan ke migration
CREATE INDEX CONCURRENTLY idx_evidence_target_gin
  ON evidence USING GIN (metadata jsonb_path_ops);

CREATE INDEX CONCURRENTLY idx_evidence_embedding_hnsw
  ON evidence USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);

CREATE INDEX CONCURRENTLY idx_evidence_timestamp_brin
  ON evidence USING BRIN (analysis_timestamp);
```


***

### 5. Tidak Ada Caching Layer yang Eksplisit

Redis sudah ada di stack, tapi perannya hanya untuk BullMQ queue.  Tidak ada caching untuk:

- **Hasil Shodan yang sama** — query IP yang sama dalam 24 jam tidak perlu hit API ulang
- **Tavily search cache** — query identik dalam window waktu tertentu
- **Entity graph traversal** dari Neo4j — path computation yang mahal

**Optimasi yang dibutuhkan:**

```python
# src/core/cache.py
import redis.asyncio as aioredis
import hashlib, json

async def cached_tool_call(tool_name: str, params: dict, ttl_seconds: int = 3600):
    cache_key = f"grond:tool:{tool_name}:{hashlib.md5(json.dumps(params, sort_keys=True).encode()).hexdigest()}"
    cached = await redis_client.get(cache_key)
    if cached:
        return json.loads(cached)
    result = await _execute_tool(tool_name, params)
    await redis_client.setex(cache_key, ttl_seconds, json.dumps(result))
    return result
```

Setiap kali analis memperbarui laporan atau menjalankan ulang investigasi, tidak ada cara untuk:

### 8. Tidak Ada Deduplication Semantik Lintas Sumber

Grond bisa mengumpulkan item yang secara semantik identik dari sumber berbeda (Shodan dan Tavily keduanya menemukan info yang sama tentang satu server).  Tanpa deduplication semantik:

- Laporan membengkak dengan redundansi
- Analyst membuang waktu membaca hal yang sama dari sudut berbeda
- Confidence scoring tidak akurat karena menghitung sumber duplikat sebagai corroboration

**Optimasi:** Gunakan pgvector yang sudah ada — sebelum menyimpan evidence baru, cek cosine similarity terhadap evidence existing dalam scope investigasi yang sama:

```python
# src/pipeline/enricher.py — tambah dedup check
async def is_semantic_duplicate(new_evidence: Evidence, threshold: float = 0.92) -> bool:
    similar = await db.query(
        "SELECT id FROM evidence WHERE 1 - (embedding <=> $1) > $2 LIMIT 1",
        new_evidence.embedding, threshold
    )
    return len(similar) > 0
```

```sql
ALTER TABLE evidence ENABLE ROW LEVEL SECURITY;
```

## Arsitektur Semantic Deduplication di Grond

Sistem ini bekerja dalam **tiga lapis** yang saling melengkapi: [^15_1][^15_2][^15_3]

```
Evidence baru masuk
        ↓
[Layer 1] Hash Exact Match      ← cepat, O(1), tangkap duplikat identik
        ↓ (jika lolos)
[Layer 2] Cosine Similarity     ← pgvector HNSW, tangkap duplikat semantik
  via pgvector                    "Shodan temukan X" ≈ "Tavily temukan X"
        ↓ (jika lolos)
[Layer 3] Cross-Source Merge    ← jika duplikat, gabung sumber bukan hapus
        ↓
Evidence unik masuk ke DB + pipeline berlanjut
```

## 1. `src/models/evidence_dedup.py` — Model Dedup

```python
from enum import Enum
from typing import Optional, List
from datetime import datetime
from pydantic import BaseModel, Field
import hashlib


class DedupDecision(str, Enum):
    UNIQUE = "unique"               # Belum pernah ada, simpan
    EXACT_DUPLICATE = "exact_dup"  # Hash identik — buang
    SEMANTIC_DUPLICATE = "sem_dup" # Konten mirip — merge sumber
    MERGED = "merged"               # Sudah digabung ke evidence existing


class DedupResult(BaseModel):
    decision: DedupDecision
    original_evidence_id: Optional[str] = None  # ID evidence yang sudah ada
    similarity_score: Optional[float] = None     # 0.0–1.0
    merged_sources: Optional[List[str]] = None   # Gabungan semua sumber
    processing_time_ms: Optional[float] = None


class EvidenceWithEmbedding(BaseModel):
    """Evidence + embedding vector siap untuk pgvector."""
    id: str
    content: str                    # Teks utama yang di-embed
    content_hash: str               # SHA-256 untuk exact match
    embedding: List[float]          # Vector dari SentenceTransformer
    source_url: Optional[str]
    source_tool: str                # "shodan", "tavily", "twitter", dll.
    investigation_id: str           # Scope dedup hanya dalam investigasi sama
    created_at: datetime = Field(default_factory=datetime.utcnow)

    @classmethod
    def compute_hash(cls, content: str) -> str:
        return hashlib.sha256(content.strip().lower().encode()).hexdigest()
```

## 2. `src/core/embedding_service.py` — Embedding Service (Async-Safe)

> ⚠️ `sentence-transformers` adalah CPU-bound synchronous library. Menjalankannya langsung di async code **akan memblokir event loop FastAPI**. Solusi: `run_in_executor`. [^15_4][^15_5]

```python
"""
Embedding service untuk semantic deduplication.

CRITICAL: sentence-transformers bersifat synchronous + CPU-bound.
Semua metode public harus async menggunakan run_in_executor()
agar tidak memblokir event loop FastAPI.
"""

import asyncio
from functools import lru_cache
from typing import List, Optional
import structlog

logger = structlog.get_logger(__name__)

# Model yang direkomendasikan untuk OSINT multi-bahasa:
# - "paraphrase-multilingual-MiniLM-L12-v2" → 50 bahasa, 384 dim, ringan
# - "all-mpnet-base-v2" → English only, 768 dim, akurasi lebih tinggi
# - "intfloat/multilingual-e5-large" → state-of-the-art multilingual
EMBEDDING_MODEL = "paraphrase-multilingual-MiniLM-L12-v2"


@lru_cache(maxsize=1)
def _get_model():
    """Lazy-load model sekali, reuse selamanya (singleton)."""
    from sentence_transformers import SentenceTransformer
    logger.info("embedding_service.model_loading", model=EMBEDDING_MODEL)
    model = SentenceTransformer(EMBEDDING_MODEL)
    logger.info("embedding_service.model_ready", model=EMBEDDING_MODEL)
    return model


def _encode_sync(texts: List[str]) -> List[List[float]]:
    """Synchronous encoding — JANGAN panggil langsung dari async context."""
    model = _get_model()
    embeddings = model.encode(
        texts,
        batch_size=32,
        show_progress_bar=False,
        normalize_embeddings=True,  # Wajib untuk cosine similarity via pgvector
    )
    return embeddings.tolist()


async def encode_texts(texts: List[str]) -> List[List[float]]:
    """
    Async-safe embedding. Offload ke thread pool agar tidak blokir event loop.
    """
    loop = asyncio.get_event_loop()
    return await loop.run_in_executor(None, _encode_sync, texts)


async def encode_single(text: str) -> List[float]:
    embeddings = await encode_texts([text])
    return embeddings[^15_0]
```

## 3. `src/pipeline/deduplicator.py` — Core Dedup Engine

```python
"""
Semantic Deduplication engine untuk Grond.
Tiga lapis: exact hash → pgvector cosine similarity → cross-source merge.
"""

import asyncio
import time
import hashlib
from typing import List, Tuple, Optional
import structlog

from src.models.evidence_dedup import (
    DedupDecision,
    DedupResult,
    EvidenceWithEmbedding,
)
from src.core.embedding_service import encode_texts
from src.core.db import get_db_pool  # AsyncPG connection pool

logger = structlog.get_logger(__name__)

# Threshold cosine similarity:
# > 0.95 → hampir pasti duplikat semantik
# 0.85–0.95 → sangat mirip, perlu merge sumber
# < 0.85 → evidence berbeda, simpan semua
EXACT_DUP_THRESHOLD = 0.97
SEMANTIC_DUP_THRESHOLD = 0.85


async def deduplicate_batch(
    evidences: List[EvidenceWithEmbedding],
    investigation_id: str,
    threshold: float = SEMANTIC_DUP_THRESHOLD,
) -> Tuple[List[EvidenceWithEmbedding], List[DedupResult]]:
    """
    Proses sekelompok evidence baru melalui tiga lapis deduplication.

    Returns:
        unique_evidences: Evidence yang lolos dedup → siap disimpan ke DB
        dedup_results: Keputusan per evidence untuk audit trail
    """
    if not evidences:
        return [], []

    t0 = time.perf_counter()

    # Encode semua teks sekaligus (batch lebih efisien)
    contents = [e.content for e in evidences]
    embeddings = await encode_texts(contents)

    # Pasangkan embedding ke evidence
    for ev, emb in zip(evidences, embeddings):
        ev.embedding = emb
        ev.content_hash = EvidenceWithEmbedding.compute_hash(ev.content)

    unique: List[EvidenceWithEmbedding] = []
    results: List[DedupResult] = []

    async with get_db_pool().acquire() as conn:
        for ev in evidences:
            result = await _check_single(conn, ev, investigation_id, threshold)
            results.append(result)

            if result.decision == DedupDecision.UNIQUE:
                unique.append(ev)
                # Simpan ke DB langsung agar evidence berikutnya bisa mendeteksinya
                await _store_evidence(conn, ev)

            elif result.decision == DedupDecision.SEMANTIC_DUPLICATE:
                # Merge sumber ke evidence existing, jangan simpan yang baru
                await _merge_sources(conn, result.original_evidence_id, ev)

    elapsed_ms = (time.perf_counter() - t0) * 1000
    logger.info(
        "deduplicator.batch_complete",
        total=len(evidences),
        unique=len(unique),
        duplicates=len(evidences) - len(unique),
        elapsed_ms=round(elapsed_ms, 2),
    )

    return unique, results


async def _check_single(
    conn,
    ev: EvidenceWithEmbedding,
    investigation_id: str,
    threshold: float,
) -> DedupResult:
    t0 = time.perf_counter()

    # === Layer 1: Exact Hash Check (O(1), paling cepat) ===
    exact_match = await conn.fetchrow(
        """
        SELECT id FROM evidence
        WHERE content_hash = $1
          AND investigation_id = $2
        LIMIT 1
        """,
        ev.content_hash,
        investigation_id,
    )
    if exact_match:
        return DedupResult(
            decision=DedupDecision.EXACT_DUPLICATE,
            original_evidence_id=str(exact_match["id"]),
            similarity_score=1.0,
            processing_time_ms=(time.perf_counter() - t0) * 1000,
        )

    # === Layer 2: Cosine Similarity via pgvector HNSW ===
    # Gunakan operator <=> (cosine distance) — 1 - distance = similarity
    similar = await conn.fetchrow(
        """
        SELECT id,
               source_urls,
               1 - (embedding <=> $1::vector) AS similarity
        FROM evidence
        WHERE investigation_id = $2
          AND 1 - (embedding <=> $1::vector) > $3
        ORDER BY embedding <=> $1::vector
        LIMIT 1
        """,
        ev.embedding,
        investigation_id,
        threshold,
    )

    if similar:
        sim_score = float(similar["similarity"])
        decision = (
            DedupDecision.EXACT_DUPLICATE
            if sim_score >= EXACT_DUP_THRESHOLD
            else DedupDecision.SEMANTIC_DUPLICATE
        )
        return DedupResult(
            decision=decision,
            original_evidence_id=str(similar["id"]),
            similarity_score=sim_score,
            merged_sources=list(similar["source_urls"] or []),
            processing_time_ms=(time.perf_counter() - t0) * 1000,
        )

    # Layer 3: Lolos semua — ini evidence unik
    return DedupResult(
        decision=DedupDecision.UNIQUE,
        processing_time_ms=(time.perf_counter() - t0) * 1000,
    )


async def _store_evidence(conn, ev: EvidenceWithEmbedding):
    await conn.execute(
        """
        INSERT INTO evidence
          (id, content, content_hash, embedding, source_urls,
           source_tool, investigation_id, created_at)
        VALUES
          ($1, $2, $3, $4::vector, ARRAY[$5], $6, $7, $8)
        ON CONFLICT (id) DO NOTHING
        """,
        ev.id,
        ev.content,
        ev.content_hash,
        ev.embedding,
        ev.source_url,
        ev.source_tool,
        ev.investigation_id,
        ev.created_at,
    )


async def _merge_sources(conn, existing_id: str, new_ev: EvidenceWithEmbedding):
    """
    Gabungkan sumber baru ke evidence existing.
    Prinsip forensik: jangan hapus evidence, tapi catat semua provenance.
    """
    await conn.execute(
        """
        UPDATE evidence
        SET source_urls = array_append(
              source_urls,
              $2
            ),
            corroboration_count = corroboration_count + 1,
            last_corroborated_at = NOW()
        WHERE id = $1
        """,
        existing_id,
        new_ev.source_url,
    )
    logger.info(
        "deduplicator.source_merged",
        existing_id=existing_id,
        new_source=new_ev.source_url,
        new_tool=new_ev.source_tool,
    )
```

```sql
-- Pastikan pgvector extension aktif
CREATE EXTENSION IF NOT EXISTS vector;

-- Tambah kolom ke tabel evidence yang sudah ada
ALTER TABLE evidence
  ADD COLUMN IF NOT EXISTS embedding          vector(384),    -- MiniLM-L12-v2 = 384 dim
  ADD COLUMN IF NOT EXISTS content_hash       TEXT,
  ADD COLUMN IF NOT EXISTS source_urls        TEXT[],
  ADD COLUMN IF NOT EXISTS corroboration_count INT DEFAULT 1,
  ADD COLUMN IF NOT EXISTS last_corroborated_at TIMESTAMPTZ;

-- HNSW index: jauh lebih cepat dari IVFFlat untuk recall tinggi
-- m=16: jumlah koneksi per node (higher = better recall, more memory)
-- ef_construction=64: tradeoff build time vs. quality
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_evidence_embedding_hnsw
  ON evidence
  USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);

-- Hash index untuk exact match (Layer 1) — O(1) lookup
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_evidence_content_hash
  ON evidence (content_hash, investigation_id);

-- Partial index hanya untuk evidence yang sudah punya embedding
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_evidence_embedding_partial
  ON evidence (investigation_id)
  WHERE embedding IS NOT NULL;
```

```python
# src/pipeline/enricher.py — tambah dedup stage di akhir enrich

from src.pipeline.deduplicator import deduplicate_batch
from src.models.evidence_dedup import EvidenceWithEmbedding
import structlog

logger = structlog.get_logger(__name__)


async def enrich_and_deduplicate(
    raw_evidences: list,
    investigation_id: str,
    dedup_threshold: float = 0.85,
) -> dict:
    """
    Fase enrichment + deduplication terintegrasi.
    Dipanggil dari LangGraph node 'enrich'.
    """
    # --- 1. Enrichment existing (domain relevance, corroboration score, dll.) ---
    enriched = await _run_existing_enrichment(raw_evidences)

    # --- 2. Konversi ke EvidenceWithEmbedding ---
    evidence_objects = [
        EvidenceWithEmbedding(
            id=ev.get("id"),
            content=_extract_content(ev),  # Gabungkan field penting jadi satu teks
            source_url=ev.get("url"),
            source_tool=ev.get("tool"),
            investigation_id=investigation_id,
            embedding=[],   # Akan diisi oleh deduplicate_batch
            content_hash="",
        )
        for ev in enriched
    ]

    # --- 3. Semantic dedup ---
    unique_evidences, dedup_results = await deduplicate_batch(
        evidence_objects,
        investigation_id=investigation_id,
        threshold=dedup_threshold,
    )

    # --- 4. Hitung statistik untuk IntelReport ---
    total = len(evidence_objects)
    exact_dups = sum(1 for r in dedup_results if r.decision.value == "exact_dup")
    sem_dups = sum(1 for r in dedup_results if r.decision.value == "sem_dup")
    merged = sum(1 for r in dedup_results if r.decision.value == "merged")

    logger.info(
        "enricher.dedup_stats",
        investigation_id=investigation_id,
        total_collected=total,
        unique=len(unique_evidences),
        exact_duplicates=exact_dups,
        semantic_duplicates=sem_dups,
        merged=merged,
        dedup_ratio=round((total - len(unique_evidences)) / max(total, 1), 2),
    )

    return {
        "unique_evidences": unique_evidences,
        "dedup_stats": {
            "total_collected": total,
            "unique": len(unique_evidences),
            "exact_duplicates": exact_dups,
            "semantic_duplicates": sem_dups,
            "dedup_ratio": round((total - len(unique_evidences)) / max(total, 1), 2),
        },
        "dedup_results": dedup_results,
    }


def _extract_content(ev: dict) -> str:
    """
    Buat teks representatif untuk embedding.
    Gabungkan field paling informatif — title + summary + key facts.
    """
    parts = []
    for field in ["title", "summary", "description", "content", "raw_text"]:
        val = ev.get(field, "")
        if val:
            parts.append(str(val)[:500])  # Batasi 500 char per field
    return " | ".join(parts)[:2000]  # Max 2000 char total
```
